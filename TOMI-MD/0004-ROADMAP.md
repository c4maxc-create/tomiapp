# خطة TOMI المعتمدة — دون مرحلة الألعاب

اعتمد المستخدم تطبيق جميع مراحل التطوير السابقة باستثناء مرحلة الألعاب. الألعاب الموجودة محفوظة كما هي ومجمدة مؤقتًا.

## ترتيب التنفيذ
1. **بوابات النسخة الحالية:** تشغيل CI حديث على أحدث commit، إصلاح فشل الاختبارات إن وجد، بناء APK حديث، ثم اختبار جهازين.
2. **المحادثات:** الروابط القابلة للنقر ومعاينة آمنة للروابط، البحث، الرد والتفاعلات والتثبيت، الوسائط وتجربة الإرسال والاستلام.
3. **الثبات:** الرفع المجزأ والاستكمال إلى R2، الفيديو والصوت، WebSocket وإعادة الاتصال، الإشعارات، إدارة الكاش والذاكرة.
4. **الأمان:** المصادقة والجلسات وMFA، صلاحيات الخادم، حماية رفع الملفات والفحص، إدارة الأسرار، النسخ والاستعادة وسجل التدقيق.
5. **تجربة المجتمع:** المنشورات والستوريات والتعليقات والبلاغات، الغرف والمكالمات، الملف الشخصي وأدوات الإدارة.
6. **الأداء والاستعداد:** قياس API والرسم والذاكرة والحمل، مراقبة وتنبيهات، اختبار استعادة ونسخة تسليم كاملة.
7. **التسليم:** تحديث سجل الحالة والمتبقي، حفظ كل الأدلة، وإنتاج ZIP موحّد يجمع أحدث مصدر مع أرشيف الاستمرارية القديم.

## قواعد لا تتغير
- لا نعدل الألعاب ولا نضيف ألعابًا جديدة في هذا النطاق.
- لا تغيّر قاعدة الإنتاج أو معرف المالك أو الأسرار أو إعدادات Firebase/MFA/R2/LiveKit دون إجراء آمن معتمد.
- لا تدّع نشرًا أو اختبارًا على هاتف أو حملًا إنتاجيًا دون نتيجة قابلة للتحقق.
- لا تضف بوابة دفع أو شحن حقيقي دون تحديد مزود الدفع وإعداداته.
- لا تضف TypeScript/Redis/Go/Rust لمجرد الاقتراح؛ القرار تابع لقياس حاجة فعلية.
- كل مرحلة تنتهي بتقرير تغييرات واختبارات وحدود، ثم أرشفة المصدر.
