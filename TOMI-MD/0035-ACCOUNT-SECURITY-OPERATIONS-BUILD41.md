# Build41 — account security and operational hardening

Requested: all twelve security proposals. This release implements the in-repository account controls and provides deployment components. It does **not** complete every proposal or claim production activation. The user confirmed there is no owned Cloudflare domain. No Render/Cloudflare/Google IAM credentials are available in this environment.

| Proposal | Result |
|---|---|
| 1. Administrator MFA and sensitive actions | Implemented authenticator enrollment, encrypted user-bound seeds, RFC6238 verification, replay prevention, ten hashed one-use backup codes, disable confirmation and 15-minute step-up. Login/recovery honor MFA; changing passwords, ending other device sessions, account deletion and administration require recent verification when enabled. Enabling/disabling ends other sessions. Requires server MFA key and user enrollment; optional mandatory staff flag after rollout. |
| 2. Devices and sessions | Existing device list/revocation/password revocation retained; sensitive revocation now honors MFA. Successful logins have private security events and existing realtime alerts. |
| 3. Object authorization | Existing server authorization/regression suite retained; no permission bypass is added by new security routes. Private security events are scoped to the current user. This is regression coverage, not a comprehensive external penetration test. |
| 4. Login abuse | IP/account pair limits persist through restart. Failed guesses across other IPs do not block a correct password. MFA verification has an additional per-user budget; valid one-use backup codes remain usable during OTP throttling. |
| 5. Files | Added real document container magic and whole-text UTF8 checks; reject executable signatures disguised by extensions. Optional streamed ClamAV integration covers image/audio/video/document verification before attachment; detected/failed/timed-out scans reject uploads. Existing checksum/type/size/private-URL controls retained. Scanner executable and current signatures need installing on hosting. Scanner unit tests use deterministic test executables, not a live antivirus database. |
| 6. WAF | Worker proxy, origin-secret checks for HTTP/WebSocket and an authenticated client-IP header are implemented and tested. Deployment/configuration pending; no owned domain and no provider credentials. Existing app endpoint remains unchanged. |
| 7. Secrets | Source ignores common local secret files; scanner remains in CI. Offline transactional MFA-key rotation tool and provider rotation instructions added. Existing Firebase private key must be revoked at Google IAM by the account owner; generating a new key alone does not revoke it. No real keys generated or changed here. |
| 8. Monitoring | Private security history and per-process last-hour401/403/429/invalid-request dashboard counters/warning thresholds added. No external alert sender/SIEM configured. Logs exclude passwords, raw session tokens, IPs and private messages. |
| 9. Backups | Existing authenticated encryption/guarded restore tools retained; a non-overwriting scheduled backup+verification runner and hardened systemd service/timer supplied. Actual PostgreSQL dump and authenticated local restore succeeded. Production scheduling, offsite storage and retention operations need hosting setup. |
| 10. Periodic verification | New scheduled/PR dependency/security workflow and Dependabot for npm/pub/NuGet/Actions. No outside penetration-testing firm commissioned; independent audit remains pending. |
| 11. E2EE | **Not implemented**. Current chats are not end-to-end encrypted. Audited protocol integration, device enrollment, attachment encryption, multi-device/history migration and recovery must be implemented and reviewed before enabling. Requirements are documented in ops/SECURITY-OPERATIONS.md; no fake secure-chat indicator was added. |
| 12. Coins/gifts | Existing server-owned prices, nonnegative balances, idempotent receipts, concurrent debit protection and trial/real-purchase separation retained and regression-tested. No payment gateway activated. |
