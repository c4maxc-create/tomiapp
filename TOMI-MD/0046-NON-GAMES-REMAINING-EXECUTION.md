# خطة التنفيذ المتبقية — TOMI دون الألعاب

آخر تحديث: 13 نوفمبر 2026. هذه الخطة هي قائمة التنفيذ النشطة للمرحلة الحالية، وليست ادعاءً بأن كل البنود منفذة.

## قواعد النطاق
- تجميد الألعاب الحالية بالكامل: لا تعديل لمحركاتها أو واجهاتها أو XP أو الروليت أو تقدم اللعب.
- الحفاظ على قاعدة البيانات الحالية وهوية المالك ومفاتيح Firebase وLiveKit وR2 وإعدادات الاستضافة.
- عدم إعادة الخادم أو قاعدة البيانات القديمة.
- لا نشر إنتاجي ولا اختبار خدمة حقيقية دون موافقة وإعدادات المالك.
- كل بند ينتقل إلى «مكتمل» فقط مع commit واختبار قابل لإعادة التنفيذ ودليل نتيجة.

## أولوية P0 — بوابات النسخة الحالية
- [ ] تشغيل API + SQLite + PostgreSQL + encrypted restore على أحدث commit وتسجيل نتيجة كل خطوة.
- [ ] تشغيل flutter analyze وflutter test وبناء Android debug APK على أحدث commit.
- [ ] مراجعة نتائج workflows بعد تغييرات روابط المحادثة و144p ونسبة الرفع.
- [ ] فحص فتح الروابط: https/www/YouTube، الروابط الطويلة وعلامات الترقيم والروابط غير الصالحة وإعادة بناء الرسائل.
- [ ] التأكد من أن artifacts تشير إلى commit الحالي، لا إلى تشغيل قديم.

## أولوية P1 — المحادثات وتجربة الاستخدام
- [ ] اختبار إرسال واستلام الرسائل وتحديثها دون إعادة تشغيل الشاشة.
- [ ] مراجعة البحث داخل المحادثات، الرد، التفاعلات، التثبيت، الحذف والحظر.
- [ ] اختبار الصور والفيديو والصوت والمرفقات والرسائل الصوتية بعد الإرسال.
- [ ] معالجة حالات التحميل والفشل وإعادة المحاولة وحالات انقطاع الشبكة.
- [ ] التحقق من صلاحيات الوصول للوسائط والروابط وعدم تسريب محتوى محادثة لمستخدم آخر.

## أولوية P1 — الثبات والوسائط والاتصال
- [ ] اختبار R2/S3 الحقيقي في بيئة staging: multipart، resume، إلغاء، retry، انتهاء presigned URL، وتنظيف الأجزاء اليتيمة.
- [ ] التحقق من renditions 144p/540p/720p مع FFmpeg، واختيار الجودة بحسب Data Saver والشبكة والجهاز.
- [ ] اختبار الفيديو على أجهزة فعلية: صورة وصوت وتزامن واتجاهات وأحجام مختلفة.
- [ ] اختبار WebSocket: reconnect، heartbeat، duplicate events، ترتيب الرسائل وتحديث الحالة.
- [ ] فحص إدارة الكاش والذاكرة والمهام الخلفية ومنع تسرب الموارد.

## أولوية P1 — الإشعارات والمكالمات والغرف
- [ ] فحص FCM في بيئة المالك: التسجيل، تحديث token، الإرسال، النقر، إلغاء التنبيه ومنع التكرار.
- [ ] اختبار مكالمات LiveKit بين حسابين وجهازين: صوت/فيديو، كتم، تبديل الكاميرا، إنهاء، انقطاع وإعادة اتصال.
- [ ] اختبار مشاركة الشاشة على الأجهزة المدعومة والتحقق من الأذونات والإيقاف عند المغادرة.
- [ ] اختبار الغرف: دخول/خروج، مقعد المالك، صلاحيات المشرف، كتم المايك، الإغلاق عند خلو الغرفة.
- [ ] اختبار الهدايا والكوينز والكارزما: خصم/إضافة مرة واحدة، منع التكرار والتلاعب، وسجل العمليات.
- [ ] اختبار الإشعارات والمكالمات في الخلفية وعلى شاشة القفل حسب قيود النظام.

## أولوية P1 — الأمان والبيانات
- [ ] مراجعة المصادقة والجلسات وMFA وتجديد/إبطال الرموز.
- [ ] مراجعة authorization على الخادم لكل عمليات الحسابات والمحادثات والمجموعات والغرف والإدارة.
- [ ] فحص رفع الملفات: MIME حقيقي، الحجم، الامتداد، أسماء الملفات، حدود المعدل، وفحص الملفات عند توفر خدمة فحص.
- [ ] التأكد من عدم وجود أسرار أو رموز أو بيانات شخصية في السجلات أو ملفات المستودع.
- [ ] تنفيذ backup/restore إلى قاعدة اختبار فارغة، ثم فحص عينات التطبيق والملفات المرجعية.
- [ ] إضافة/مراجعة سجل تدقيق للإجراءات الإدارية والمالية الحساسة.

## أولوية P2 — المجتمع والإدارة
- [ ] اختبار المنشورات والقصص والتعليقات والإعجابات والبلاغات والحظر والإبلاغ.
- [ ] مراجعة خصوصية الملف الشخصي والمتابعين والظهور والوصول إلى المحتوى.
- [ ] اختبار صلاحيات المالك والمشرفين: الحظر، القراءة فقط، منح الأدوار وإلغاؤها.
- [ ] مراجعة لوحة المراقبة: أخطاء API، زمن الاستجابة، الذاكرة، الغرف والمهام، مع توضيح حدود القياس.

## أولوية P2 — الأداء والتسليم
- [ ] تشغيل اختبارات حمل متدرجة في staging مع تسجيل التزامن وزمن الاستجابة والأخطاء والذاكرة.
- [ ] عدم اعتماد هدف 1000 مستخدم قبل قياس موارد API وPostgreSQL وR2 وLiveKit فعليًا.
- [ ] إعداد تنبيهات خارجية لانقطاع الخدمة وأخطاء الخادم وامتلاء الموارد.
- [ ] تجربة استعادة نسخة قاعدة البيانات وملفات R2 في بيئة منفصلة.
- [ ] بناء APK حديث وتوثيق الأجهزة وإصدارات Android ونتائج الاختبارات.
- [ ] تحديث سجل الحالة والمتبقي ثم إنشاء ZIP موحد من أحدث commit مع أرشيفات الاستمرارية السابقة.

## اختبارات تتطلب المالك أو أجهزة حقيقية
تتطلب بيانات staging وموافقة المالك: R2/S3 وFirebase/FCM وLiveKit وRender، واختبار جهازين، واختبار حمل خارجي. لا تُستبدل هذه الاختبارات بمحاكاة CI ولا تُسجل مكتملة قبل ظهور نتائجها.

## حالة التنفيذ عند إنشاء هذه الخطة
- سبق نجاح بعض بوابات CI: Android debug smoke، Security، وAPI/PostgreSQL restore على commits سابقة محددة.
- آخر مصدر معروف عند بدء هذه الخطة: `f8d217d436568efe675ede15872385c11e8b4aab`.
- نجاح CI على commit سابق لا يثبت نجاحه على أي commit لاحق.
- الألعاب مؤجلة بالكامل حسب طلب المستخدم.
