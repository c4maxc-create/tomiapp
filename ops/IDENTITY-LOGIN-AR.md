# تفعيل Google والهاتف وFacebook وApple — بناء42

الكود متصل بـFirebase Authentication ثم يتحقق الخادم من توقيع Google ومشروع Firebase وهوية المستخدم. إنشاء الحساب وربط الطرق عمليتان منفصلتان: لا ندمج حسابين اعتماداً على البريد أو الاسم. يحتفظ الدخول بكلمة المرور بحساباته الحالية. الحساب الخارجي الجديد له حساب TOMI مستقل، ويمكن ربط طرق أخرى به من الإعدادات بعد تأكيد الهوية. المصادقة بخطوتين في TOMI تبقى مطلوبة إذا سبق تفعيلها.

**الحالة:** التنفيذ والاختبارات موجودان، لكن لا توجد للجلسة صلاحية تفعيل مزوّدي حساباتك. لا تُعتبر الطرق الأربع مفعلة في الإنتاج بمجرد رفع المصدر. لا ترسل مفاتيح أو JSON إداري في المحادثة.

## إعداد Firebase المشترك

1. افتح مشروع `tomi-218ba` → Authentication → Get started → Sign-in method.
2. فعّل الطرق التي تجهزها فقط. راجع إعداد حسابات البريد: لا تسمح بدمج طرق مختلفة تلقائياً لمجرد تشابه البريد إذا كنت تريد هويات منفصلة. اربط الطرق من إعدادات TOMI بعد تأكيد الدخول.
3. في Render → Environment أضف `TOMI_FIREBASE_PROJECT_ID=tomi-218ba`، و`TOMI_AUTH_PROVIDERS` بقائمة الطرق المجهزة فعلياً فقط، مثل `google,phone,facebook,apple`. القيمة الافتراضية فارغة؛ لا نعرض طريقة كجاهزة وهي غير مفعلة.
4. انشر الخادم الجديد يدوياً، وابنِ نسخة هاتف جديدة. ملف Firebase الخاص بالعميل يجب أن يكون من نفس المشروع. تحقق الخادم من الدخول لا يحتاج مفتاح Admin SDK؛ مفتاح الإشعارات القديم موضوع منفصل ويحتاج تدويراً.

## Google

- فعّل Google وحدد بريد الدعم.
- سجّل SHA-1 وSHA-256 لشهادة النسخة التي ستثبتها في Firebase → Project settings → تطبيق Android. للتفعيل الدائم استخدم بناء `signed_beta` بمفتاح توقيعك الثابت. بناء debug على جهاز GitHub جديد قد يولّد شهادة مختلفة، فلا تعتمد على بصمة debug من بناء سابق.
- نزّل `google-services.json` الجديد بعد تفعيل Google وبصمات OAuth. حدّث GitHub Secret الموجود لإعداد Firebase الخاص بعميل Android، وليس ملف service-account. أسماء أسرار البناء الحالية موثقة في workflow Android.
- للآيفون أضف تطبيق iOS بمعرّف `com.tomi.tomiapp` وحدّث `TOMI_IOS_GOOGLE_SERVICES_PLIST`. يضيف bootstrap عنوان الرجوع وGIDClientID من ملف العميل.

## رقم الهاتف

- فعّل Phone في Firebase واضبط SMS region policy للسماح بالبلدان المطلوبة ومنها العراق.
- راجع متطلبات خطة الفوترة وحصة SMS والأسعار في حساب Firebase؛ لا يوجد وعد بأن الرسائل مجانية أو متاحة بكل بلد.
- فعّل التحقق من التطبيق وبصمات Android. اختبر أولاً بأرقام الاختبار المخصصة في Firebase دون إرسال رسائل حقيقية.
- آيفون يحتاج إعداد APNs والتحقق من التطبيق وعنوان الرجوع وفق دليل Firebase Phone Auth. اختبر على هاتف حقيقي. الرمز يثبت ملكية الرقم؛ لا يستخدم التطبيق الرقم لدمج حسابات TOMI موجودة تلقائياً.

## Facebook

- أنشئ تطبيق Meta وهيئ Firebase Facebook Login. App Secret يوضع داخل Firebase Console فقط، ولا يضاف إلى APK أو المستودع.
- أضف رابط OAuth redirect الذي يعرضه Firebase إلى Meta، وحزمة Android وkey hashes وشروط الخدمة/الخصوصية وحذف البيانات المطلوبة.
- GitHub Variable: `TOMI_FACEBOOK_APP_ID`. GitHub Secret: `TOMI_FACEBOOK_CLIENT_TOKEN` (Client Token الخاص بتطبيق العميل، **ليس App Secret**).
- راجع وضع Live وصلاحيات تطبيق Meta. يستخدم iOS Limited Login مع nonce. تتبع الإعلانات وتسجيل أحداث Meta التلقائي معطلان افتراضياً؛ plugin لا يهيئ Facebook عند تشغيل TOMI دون إعداداته.

## Apple

- يلزم حساب Apple Developer وإضافة Sign in with Apple إلى App ID ومعلومات الخدمة والمفتاح داخل Firebase Console. مفتاح Apple الخاص لا يدخل التطبيق أو GitHub.
- جهز Service ID وreturn URL المطلوبة لدخول Apple عبر Android، وفعّل إمكانية Sign in with Apple لملف توقيع iOS الحقيقي.
- bootstrap يضيف entitlement `com.apple.developer.applesignin`; المحاكي لا يثبت نجاح الدخول الإنتاجي ولا يحل محل ملف التوقيع.
- راجع Apple Private Email Relay إذا ستستخدم البريد المخفي وإرسال بريد للمستخدم.

## التحقق قبل الإعلان

جرب كل طريقة على هاتف: إنشاء حساب، خروج ودخول لنفس الحساب، إلغاء شاشة المزوّد، انقطاع الشبكة، رمز هاتف خاطئ، حساب موجود بمزوّد آخر، ربط طريقة بعد تأكيد الهوية، MFA، حذف الحساب. لا تعلن اكتمال التفعيل قبل نجاحها. حذف TOMI يمسح ربط الهوية والبيانات داخل TOMI؛ حذف مستخدم Firebase نفسه يحتاج عملية إدارة منفصلة موثوقة، ولا نمحو مستخدم Firebase تلقائياً من العميل قبل تأكيد حذف TOMI.
